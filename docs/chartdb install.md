# Как запустить ChartDB в Docker на Windows 10 или 11

ChartDB строит ER-диаграммы базы данных: показывает таблицы, столбцы и связи между таблицами. В этой инструкции вы запустите ChartDB локально и импортируете схему PostgreSQL через DBeaver. Для запуска редактора не нужен PostgreSQL, а для импорта схемы не нужно вводить пароль от базы в ChartDB. Ключ OpenAI для этих шагов не требуется.

## Шаг 1. Проверьте Docker Desktop

Если Docker ещё не установлен, пройдите [инструкцию по установке Docker Desktop](Docker%20install.md). Запустите Docker Desktop, дождитесь запуска движка и откройте **Windows PowerShell**. Выполните:

```powershell
docker info --format '{{.OSType}}'
```

Ожидаемый результат — `linux`. Если команда не подключается к Docker, проверьте, что Docker Desktop запущен. Если выводится `windows`, переключите Docker Desktop в режим Linux-контейнеров.

## Шаг 2. Запустите ChartDB

Вставьте команду целиком в PowerShell:

```powershell
docker run -d --name chartdb -p 127.0.0.1:8090:80 -e DISABLE_ANALYTICS=true ghcr.io/chartdb/chartdb:latest
```

При первом запуске Docker скачает официальный образ ChartDB. `-d` запускает контейнер в фоне, а `127.0.0.1:8090:80` направляет порт `8090` на вашем компьютере на порт `80` в контейнере. Интерфейс предназначен для доступа с этого компьютера. Порт `8090` отличается от `8088`, который используется в инструкции по Airflow.

Проверьте состояние:

```powershell
docker ps --filter name=chartdb
```

В списке должен появиться `chartdb` со статусом `Up` и портом `127.0.0.1:8090->80/tcp`. Откройте в браузере [http://127.0.0.1:8090](http://127.0.0.1:8090). Если появился стартовый экран ChartDB, контейнер работает.

## Шаг 3. Импортируйте схему PostgreSQL

Для этого шага нужна база с таблицами. Можно использовать `appdb` из инструкции [PostgreSQL в Docker и DBeaver](postgresql%20install.md). Если вы уже восстановили учебную копию, можно взять её вместо `appdb`.

1. В ChartDB перейдите в редактор (**Go to app**, если отображается стартовый экран) и создайте диаграмму для **PostgreSQL**.
2. Выберите импорт через **Smart Query** и скопируйте SQL-запрос, который покажет ChartDB.
3. В DBeaver откройте **SQL Editor** для нужной базы. Вставьте запрос и нажмите `Ctrl + Enter`. Запрос читает метаданные схемы; пароль остаётся в DBeaver, а ChartDB получает только результат, который вы вставите вручную.
4. В результатах DBeaver откройте ячейку с JSON в редакторе значения и скопируйте её содержимое целиком. Не копируйте имя столбца и не экспортируйте результат как CSV.
5. Вернитесь в ChartDB, вставьте JSON в поле импорта и подтвердите. Если использовали учебную `appdb`, на диаграмме должна появиться таблица `public.notes` со столбцами `id` и `title`. Связей у неё нет — это нормально: они появятся у таблиц с внешними ключами.

Если диаграмма нужна как артефакт занятия, экспортируйте её через меню **Export**. Не рассчитывайте на браузер как на единственное место хранения: очистка данных сайта, другой профиль браузера или смена адреса и порта могут сделать локальные диаграммы недоступными. Перед публикацией проверьте, что схема не раскрывает внутренние данные проекта.

## Шаг 4. Остановите и запустите ChartDB снова

```powershell
docker stop chartdb
docker start chartdb
```

Первая команда останавливает контейнер, вторая запускает его снова. Повторять `docker run` не нужно: эта команда создаёт новый контейнер, а имя `chartdb` уже занято.

## Если что-то не получилось

| Симптом | Что сделать |
| --- | --- |
| `The container name ... is already in use` | Выполните `docker ps -a --filter name=chartdb`. Если это ваш контейнер и он остановлен, выполните `docker start chartdb`. Если уже запущен, посмотрите опубликованный порт в выводе. |
| `port is already allocated` или `Only one usage of each socket address...` | Если неудачный запуск оставил новый контейнер `chartdb` в состоянии `Created`, удалите именно его командой `docker rm chartdb`. Повторите команду из шага 2 с `127.0.0.1:8091:80`, а в браузере откройте `http://127.0.0.1:8091`. |
| Браузер не открывает страницу | Проверьте `docker ps -a --filter name=chartdb` и `docker logs --tail 50 chartdb`. Используйте `http://`, а не `https://`, и порт из команды запуска. |
| Импорт сообщает, что JSON невалиден | Скопируйте полное содержимое ячейки результата, без заголовка, обрезки или дополнительных кавычек от CSV. Проверьте, что запрос выполнился без ошибки. |
| Импорт прошёл, но нет нужных таблиц | Проверьте активную базу в DBeaver командой `SELECT current_database();`, наличие таблиц и права пользователя на нужную схему. |

Документация: [официальный репозиторий ChartDB](https://github.com/chartdb/chartdb) · [импорт схемы PostgreSQL](https://docs.chartdb.io/docs/import/postgresql).
