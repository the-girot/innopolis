# Восстановление PostgreSQL из резервной копии

Восстановим логический дамп одной базы в новую базу `appdb_restore`, не меняя рабочую `appdb`. Команды рассчитаны на Windows PowerShell и контейнер `pg-local` из инструкции [PostgreSQL в Docker и DBeaver](postgresql-docker-dbeaver.md). Устанавливать `psql` и `pg_restore` в Windows не нужно: они уже есть в контейнере.

> Восстанавливайте только доверенные копии. Дамп может содержать исполняемые SQL-команды. Если файл получен из неизвестного источника, не загружайте его в контейнер с важными базами. Если копия содержит персональные данные или секреты, не загружайте её на GitHub.

## 1. Определите формат

| Что у вас | Как восстановить |
| --- | --- |
| Архив `pg_dump` в формате Custom или Tar, обычно `.dump`, `.backup` или `.tar` | `pg_restore`. Команда `--list` ниже проверяет, читается ли оглавление архива. |
| Обычный текстовый дамп одной базы, обычно `.sql` | `psql`. Перед загрузкой проверьте, что это не скрипт восстановления всего сервера и в нём нет `CREATE DATABASE` или `\connect`, переключающих работу на другую базу. Если есть — запросите дамп без создания базы или восстановите его в отдельном изолированном экземпляре по согласованной процедуре. |
| Файл `.sql.gz` или `.zip` | Если это внешняя упаковка, сначала распакуйте и определите формат содержимого. |
| Каталог с `toc.dat` от `pg_dump -Fd` | Это формат Directory: скопируйте весь каталог через `docker cp` и передайте `pg_restore` путь к каталогу, а не к `toc.dat`. |
| Каталог `PGDATA`, копия Docker-тома, `pg_basebackup` или SQL от `pg_dumpall` | Эта инструкция не подходит: у физической копии и копии всего сервера другой порядок восстановления. |

Расширение файла — подсказка, а не гарантия формата. Если знаете версию исходного PostgreSQL, выбирайте для восстановления ту же основную версию или совместимую более новую; загрузка из более новой версии в старую не гарантируется. Для дампа нужны совместимые клиентские утилиты и установленные в целевом сервере расширения, которые использовала исходная база.

## 2. Подготовьте пустую базу

Запустите Docker Desktop и контейнер `pg-local`, если он остановлен. В PowerShell выполните:

```powershell
docker exec pg-local pg_isready -h 127.0.0.1 -U postgres
docker exec pg-local createdb -U postgres -T template0 appdb_restore
```

Первая команда должна показать `accepting connections`. Если вторая сообщает, что `appdb_restore` уже существует, **не продолжайте поверх неё**: выберите новое имя, например `appdb_restore_2`, и подставьте его во все следующие команды и настройки DBeaver.

## 3. Восстановите одним из способов

Замените путь `C:\Backups\...` на фактический путь к файлу. Кавычки нужны, если путь содержит пробелы. Выполняйте команды по одной; если команда сообщила об ошибке, остановитесь.

### Вариант A: архив `.dump`, `.backup` или `.tar`

```powershell
docker cp "C:\Backups\appdb.dump" pg-local:/tmp/appdb.dump
docker exec pg-local pg_restore --list /tmp/appdb.dump
```

Если оглавление выводится без ошибок, выполните восстановление:

```powershell
docker exec pg-local pg_restore -U postgres -d appdb_restore --single-transaction --exit-on-error --no-owner --no-acl /tmp/appdb.dump
$LASTEXITCODE
```

`0` означает, что команда завершилась успешно. `--single-transaction` выполняет восстановление целиком в одной транзакции: при ошибке изменения откатываются. `--no-owner` и `--no-acl` не переносят исходных владельцев и права доступа — это удобно для локальной копии, но не подходит, когда права нужно сохранить. Отдельные ссылки на роли, например в политиках доступа, всё равно могут потребовать существующих ролей.

### Вариант B: текстовый файл `.sql`

Эти команды рассчитаны на обычный текстовый дамп **одной базы** от `pg_dump`, без параметра `--create`:

```powershell
docker cp "C:\Backups\appdb.sql" pg-local:/tmp/appdb.sql
docker exec pg-local psql -X -U postgres -d appdb_restore -v ON_ERROR_STOP=1 --single-transaction -f /tmp/appdb.sql
$LASTEXITCODE
```

`ON_ERROR_STOP=1` останавливает скрипт при SQL-ошибке. `--single-transaction` позволяет откатить изменения при ошибке для обычного дампа; скрипты с собственными командами управления транзакциями или командами, запрещёнными внутри транзакции, требуют отдельной процедуры. Если есть возможность заново экспортировать дамп для локальной базы, попросите текстовый экспорт с `pg_dump --no-owner --no-acl`.

## 4. Проверьте результат в DBeaver

1. Создайте отдельное подключение **PostgreSQL**: Host — `127.0.0.1`, Port — `15432` (или порт из вашей настройки), Database — `appdb_restore`, Username — `postgres`, Password — пароль из инструкции запуска. Нажмите **Test Connection**, затем **Finish**.
2. Откройте SQL Editor именно для нового подключения, выполните запросы по очереди:

   ```sql
   SELECT current_database();

   SELECT schemaname, tablename
   FROM pg_catalog.pg_tables
   WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
   ORDER BY schemaname, tablename;
   ```

3. Убедитесь, что выбрана `appdb_restore`, найдите нужные таблицы и сравните количество строк и несколько контрольных записей с исходной базой или ожидаемыми значениями. Например, если дамп сделан после первой инструкции, выполните `SELECT count(*) FROM public.notes;` — для учебного примера ожидается `1`.
4. После проверки можно удалить только временную копию файла **внутри контейнера** (`docker exec pg-local rm -f /tmp/appdb.dump` или `docker exec pg-local rm -f /tmp/appdb.sql`). Оригинал на Windows сохраните отдельно.

## Типовые ошибки

| Ошибка | Что делать |
| --- | --- |
| `input file appears to be a text format dump` | Это текстовый SQL, используйте вариант с `psql`. |
| `unsupported version ... in file header` | Проверьте, какой версией `pg_dump` создан архив. Используйте `pg_restore` той же или более новой совместимой версии. При необходимости поднимите отдельный контейнер с новым томом; не меняйте основную версию образа поверх существующего тома. |
| `role ... does not exist` | Для локальной копии используйте архив с `--no-owner --no-acl` при восстановлении или запросите текстовый дамп без владельцев и прав. Если объект действительно зависит от конкретной роли, согласуйте её создание. |
| `extension ... is not available` | Подготовьте образ PostgreSQL, в котором установлено нужное расширение совместимой версии. Повторите восстановление в пустую базу. |
| `relation ... already exists` | Проверьте, что восстановление идёт в пустую базу. Не добавляйте `--clean` к команде для рабочей базы: этот параметр удаляет объекты перед восстановлением. |

Документация PostgreSQL: [резервное копирование SQL-дампом](https://www.postgresql.org/docs/current/backup-dump.html) · [pg_restore](https://www.postgresql.org/docs/current/app-pgrestore.html) · [psql](https://www.postgresql.org/docs/current/app-psql.html).
